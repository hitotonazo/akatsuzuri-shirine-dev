## 1. 作品概要・目的

- 作品名：**赤綴神社**（あかつづりじんじゃ）
- 日本語キャッチコピー：**「願いを結び、日々を穏やかに。」**
- 想定プレイ：20～60分、一本道、通常サイトから謎・真相へ遷移する異常発見型ARG。
- 表面：朱塗りの立派な社殿を持つ、由緒ある架空の神社公式サイト。健康祈願・縁結び・商売繁盛・神事・御守・御朱印・絵馬・Web参拝・地域支援会を普通に紹介する。
- 裏面：本来の神「受代ノ御影」は苦難を別人へ移す。富裕層向けの秘密祈願は生活支援会利用者を身代わりにしていた。身代わり制度が破綻し先代宮司は死亡。現宮司は残余の災いから逃れるためWeb参拝で不特定多数を登録し、神は承認なしに参拝者間で願いと災いを割り当てる。プレイヤーの参拝番号も候補として記録されていた。
- プレイヤー本人の実際の個人情報、病歴、住所、IP、位置情報、指紋等は取得しない。参拝番号はブラウザ内のみで成立する**フィクションの識別記録**。

## 3. デザイン基準

### 3-1. 視覚の方向性

- ユーザー承認済み `hero-slide-01` の建築と意匠が絶対基準：**大型の朱塗り拝殿、黒〜濃灰の屋根、金装飾、石畳、落ち着いた緑の境内**。実在神社を模写しない。
- 写真生成済み・修正済みの素材を用いる。ロゴや画像をCodeXの判断で生成し直さない。
- 添付の参考デザインの要素：大きいヒーロー、白～生成りの背景、広い余白、縦書き見出し、写真＋文章の左右組み、控えめな朱色、視認性を優先。
- **波・曲線のセクション区切りは禁止**。安定した直線・余白・薄い罫線に限定。
- ゲーム開始時にノイズ、赤い点滅、不気味な音、不吉な影、ホラーコピーなどの「通常サイトを壊す」表現を入れない。

### 3-3. フォント

- 日本語見出し：**Shippori Mincho**。

- Webフォント読み込みに失敗しても日本語可読性を維持するフォールバックを設定。

## 5. スライドショー

- `hero-slide-01`～`hero-slide-05`を順に表示し、1→2→3→4→5→1でループする。

## 6. ファイル・SCSS・JavaScript案

> 次の構造は `modules/` を確認した後の実装配置**案**。実際の既存フォルダ構造が異なれば勝手に移動・破壊せず、差分と対応策を報告する。

```text
project/
  index.html / about.html / events.html / ema.html / worship.html
  visit.html / donation-record.html / old-record.html / truth.html
  assets/
    images/              # 03に定義する命名へ、確認済み画像を配置

    scss/
      style.scss         # 唯一のSCSS入口

      layout/            # header、footer、container
      component/         # button、modal、slider、document
      page/              # 各ページ固有（共通レイアウトを再定義しない）
    css/style.css        # コンパイル出力（直接編集禁止）
    js/
      game.js            # stateと作品固有イベントの統合
      pages.js           # ページ別初期化
  modules/               # ユーザー既存。必ず中身を読んで再利用

  README.md
```

推奨npm scripts（`modules/`や既存package設定を確認してから採用）：

```json
{
  "scripts": {
    "build:css": "sass assets/scss/style.scss assets/css/style.css --style=compressed --no-source-map",
    "watch:css": "sass --watch assets/scss/style.scss:assets/css/style.css"
  }
}
```

- SCSS編集→ `npm run build:css`→ 実CSS更新確認→ブラウザ再検証が作業完了条件。`assets/css/style.css`へ手書きする運用は禁止。
- Header/Footer、ゲームstate、共通コンポーネントはページごとにばらばらに複製せず、読み込み方式を統一。採用方式が既存環境に合わせられない場合は理由を報告。

## 8. ゲームstateの共通方針

- `localStorage` は作品固有の名前空間で保存（例：`akatsuzuri:v1`）。既存moduleのキーとの衝突を検査。
- 読み出し時の型検証・version確認・不正JSONからの安全復旧。stateスキーマ詳細は `02_game-flow.md`。
- リセットは**確認ダイアログ→ゲーム用stateのみ消去→TOPへ遷移**。利用者の他サービスや他作品のlocalStorageを一括消去しない。
- 一度発見した異常は再訪しても残る。モジュールによる「サイトが改変されました」は**初回クリア時の1回だけ**。
