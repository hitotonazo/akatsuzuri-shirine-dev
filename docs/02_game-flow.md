# 02_game-flow.md — 赤綴神社｜PHASE・操作・状態管理仕様

> **必読：実装開始前に `00_project.md` → `01_pages.md` → `02_game-flow.md` → `03_truth-ending-images.md` の順に4ファイルをすべて確認すること。1ファイルだけを読んで実装を開始しない。**
>
> 重要異常はPHASE1＝絵馬1枚、PHASE2＝祭神画1枠、PHASE3＝古文書写真1枠。以後の内部資料・写真・説明はこの異常の内部展開であり、独立した新異常にしない。

## 1. 標準導線（一本道）

```text
PHASE0: index → worship（通常の鈴／参拝番号発行）→ ema
PHASE1: ema（赤文字入り絵馬へ完成画像差替→クリック）→ donation-record
PHASE2: donation-record → about（祭神画切替→異常画クリック）→ old-record
PHASE3: old-record → events#archive（写真差替→帳面①②③④を順番に閲覧→第四帳内の「閲覧する」→資料①②③④）
TRUTH: events（統合記録へ）→ truth（真相6セクション、Ending、X共有）
```

- 通常サイトの他ページ（TOP、神社について、年間行事、絵馬、Web参拝、参拝案内）は自由に閲覧できる。**異常の発火条件**は必ず守る。
- 発見済み異常は残す。戻った時に元に戻らない。どの経路でサイトに戻っても、発見済みの操作は再び実行できるが「サイトが改変されました」を重複再生しない。
- 手順のスキップ、複数異常の同時出現、隠し分岐、別Ending、ランダムに変わるストーリー／事故は作らない。

## 2. 状態（名前と型の推奨スキーマ）

**作品固有ローカル状態の例**。実際の`modules/`に保存形式がある場合は衝突検証後に接続・整合する。**未確認のモジュール関数は推測して呼ばない**。

```js
const STORAGE_KEY = 'akatsuzuri:v1';
const initialState = {
  schemaVersion: 1,
  phase: 0,                 // 0=通常、1=絵馬発見済、2=祭神発見済、3=四冊読了済、4=真相到達済
  hasWorshipped: false,
  visitId: null,            // WEB-で始まる架空番号、個人情報との関連なし
  discovered: {
    ema: false,
    deity: false,
    archive: false
  },
  readBooks: [false, false, false, false],
  supportRecordsViewed: false,
  truthViewed: false,
  endingViewed: false,
  modificationPlayed: {
    ema: false,
    deity: false,
    archive: false
  }
};
```

### 保存ルール

- **一つの作品キー**にjsonとして保存。既存モジュールが別キーを所有するなら仕様を確認して衝突防止。
- すべてのページで**初期化→整合性チェック→表示**の順番を統一する。
- `visitId`は初回Web参拝で一度だけ生成。再クリック、再読込、ブラウザバック、再訪問で変わらない。`reset`時にのみ破棄。
- `phase`は基本的に増加のみ（デバッグ／リセット例外）。低い状態へ自動的に逆戻りしない。
- `discovered`と`modificationPlayed`は**別に保持**し、画像出現とモジュール演出実行の重複を防ぐ。
- 不正JSON、不足属性、異常値、旧schemaVersionなら、安全な初期状態へ復旧。復旧後にアクセス不可の真相情報を表示しない。
- 同時に複数タブを使った場合、少なくとも再読込時には永続化したフラグと一致するようにする。

### 参拝番号

- 表記：`WEB-`＋0埋め数字、例`WEB-00482`。この番号はフィクション。実際の訪問者を追跡するIDやサーバー一意IDではない。
- 候補実装：ブラウザ内の安全な乱数に基づく5桁整数（既存環境が許すAPIを利用）を初回参拝時のみ保存。番号が偶然他人と重複しても問題ない演出であり、外部問い合わせやIDデータベースは不要。
- 実際の氏名、連絡先、顔画像、健康状態、IP、位置情報、UA等と結びつけない。
- 当人へ超常的な「健康・災いの診断」を実際に行っているかのような個人判定表示をしない。物語上の「身代わり候補」固定文言に留める。

## 4. PHASE0 — 普通のWeb参拝

- 初期画面は`index.html`、普通の神社のTOP。ゲーム説明・「探索開始」警告などを新設しない。
- プレイヤーが`worship.html`のイラスト中央の鈴をクリック。
- 音が鳴る→`visitId`を初回生成→参拝完了メッセージ。**「サイトが改変されました」を再生しない。**
- 参拝を完了させず`ema.html`へ行っても、すべて普通の絵馬のまま。
- 完了後は普通に「奉納絵馬を見る」リンクを案内。前の写真・文言が怪しく変わることはない。
- Endingでは**同じ社殿のイラスト・鈴**および**同じvisitId**を使う。

## 5. PHASE1 — 一枚の絵馬のみ

1. `ema.html`の通常画像群に混じる病気平癒の一枚を見せる。願い文「長年の病気が治りますように。」は画像内に記録されている。
2. Web参拝済みで、一定時間閲覧すると**当該1枚だけ**`ema-closeup-health-anomaly.jpg`へ差し替える。赤文字「この願いは叶いましたが……今でも罪悪感があります。」は別の実画像内。
3. プレイヤーがその絵馬をクリックした時に`discovered.ema=true`、`phase=1`を永続化し、**既存modulesによる改変演出を一度だけ**出す。演出終了後に`donation-record.html`へ遷移。
4. 再訪：赤文字版を即時表示。クリックしても演出を再再生せず内部資料へ普通に遷移する。
5. 本物の絵馬としての妥当性：**通常は願いを書く絵馬である**。旧骨子の「願望成就報告ばかりのギャラリー」「病気が完治しました」の元の絵馬へ戻さない。

## 6. PHASE2 — 祭神の画像一枠のみ

1. `phase>=1`の`about.html`で`deity-normal.jpg`と`deity-hidden.jpg`を同一枠で数秒ごとに表示切替。
2. ほかの神社写真、御祭神本文、ナビ、背景などは異常に変えない。
3. 黒い祭神画（受代ノ御影）表示時のクリックにのみ意味がある。タイミングを逃しても再表示する。キーボード操作時も対象が分かるようにする。
4. 初回クリックで`discovered.deity=true`,`phase=2`を保存し、modulesの改変演出を一度だけ再生後、`old-record.html`。
5. 再訪：過去の異常は残す。異常画を再度クリックしても同じ演出を流さない。

## 7. PHASE3 — 一枚の古文書写真から四冊へ

### 7-1. 初期状態

- `phase<2`：`events.html#archive`に`archive-normal.jpg`、hotspotなし。
- `phase>=2`：**同じ写真枠**を`archive-changed.jpg`に切替。四冊だけが赤く目立ち、他の巻物や資料と背景は暗い。画面全体や別セクションには新しい異常を出さない。

### 7-2. 四冊の順序

| 順 | ボタン／内容 | 記録するstate | 次の解放 |
|---|---|---|---|
| 1 | 災いの記録 | `readBooks[0]=true` | 2冊目 |
| 2 | 身代わり名簿 | `readBooks[1]=true` | 3冊目 |
| 3 | 神との契約記録 | `readBooks[2]=true` | 4冊目 |
| 4 | 身代わり管理記録 | `readBooks[3]=true`（内容閲覧後） | 「閲覧する」ボタン |

- 帳面は**写真内に重ねたhotspot**を選択。クリック位置は完成画像に合わせて実測し、SPの`object-fit`／オリジナル画像比率に追随させる。各hitboxは44px以上目安。画像領域外や重なったクリック判定は禁止。
- 初回に表示するのは**①だけ**。各ポップアップの読了後、次の帳面が選べる。すでに読んだ帳面は再閲覧可能で、読了フラグはリセットされない。
- ポップアップを閉じてもprogressは維持。画面外へスクロールした場合も次の帳面が分かるような案内。
- 4冊目の「閲覧する」クリック後、黒背景を同ページ内の閲覧セクションとして展開する。ページ遷移は禁止。
- 資料①生活支援会→資料②本人に知らせない候補登録→資料③旧制度停止→資料④Web参拝へ運用変更。**4つの資料は固定順で縦スクロール**。自動フェードは読み終わる前に隠さない。
- 4資料表示後の最後のCTAのみが`truth.html`への入口。初回クリックで`discovered.archive=true`,`phase=3`および改変演出。必要なら演出後に遷移。

### 7-3. 真相の情報を前倒ししない

- PHASE3では「Web参拝の鈴鳴らしが新しい登録源だった」までは提示してよい。
- **鈴が神社の実物と連動する仕組み、神が宮司の承認なしに無差別な願いの割当を行っていること、プレイヤー本人の番号照合**は`truth.html`まで明かさない。

## 8. 真相・Ending

- PHASE3終了前に`truth.html`の本文、事故番号、プレイヤーの候補表示を覗けないこと（ルーティング上／初期レンダリング上の漏れを防ぐ）。
- `truth.html`は6セクション＋X共有を縦方向で読む。一度見た資料・情報を奇妙な英語だけで表示しない。
- 受代ノ御影による願いの成就は**無からの幸運創造ではなく災いの転嫁**。正式契約は3年、Web参拝による厄分けは鈴だけで一時候補、というルールを混同しない。
- 初回Endingでは現在の参拝番号を取得し、「身代わり候補：登録済」「割当状態：待機中」「次回の転嫁対象：未確定」。被害が確定したとは表示しない。
- 「次の身代わりは、まだ決まっていません。」「現在もWeb参拝を受け付けています。」を固定文言として表示。
- Endingの背景は`ending-ledger.jpg`、Web参拝と同じ`worship-illustration.jpg`／同じ鈴の構図を補助表示。番号自体はHTMLテキストで重ねる（写真に個別番号を焼き込まない）。
- X共有はクリックでSNSの投稿準備を開く。指定文に個別番号を混ぜない。詳細は03。

## 9. 直接URL／再読み込み／Historyの扱い

| ケース | 期待結果 |
|---|---|
| 参拝せずに `ema.html` | 普通の絵馬のみ。操作の解放なし |
| 未達で `donation-record.html` 直入力 | 内部資料を見せず、通常のTOP等へ戻す。新規403ページは作らない |
| 未達で `old-record.html` 直入力 | 祭神の真相を表示せずTOP等へ戻す |
| 未達で `truth.html` 直入力 | 真相を表示せずTOP等へ戻す |
| 発見後に該当ページをリロード | 元の状態に巻き戻さず、発見済みの画像・資料を復元 |
| ブラウザBack/Forward | `pageshow`を含め現在stateに応じて再評価。二重改変、未解放の真相表示がない |
| 別URLから既読資料へ戻る | 一度読んだ帳面・資料の開放状態が維持 |
| プレイヤーが真相からTOPへ戻る | 通常TOPは通常の見た目。異常の解放状態は保持 |
| リセット後にBackで真相へ戻る | 真相は出さない。ゲート判定を再度適用 |

**備考：** これはゲーム上の表示制御であり、ブラウザからHTMLソースを完全秘匿するセキュリティではない。実際のソースでネタバレを不可視にする方式は既存実装と相談。通常プレイでの順序破綻をまず防ぐ。

## 10. モジュールの改変演出と再訪の制御

- **必ず**既存`modules/`の演出を利用する。勝手な別デザインの赤いフラッシュ／独自ローディング画面へ置き換えない。
- 初回の「重要異常を発見しPHASEが進行した時」に原則1回のみ再生：絵馬クリック／隠された祭神画像クリック／PHASE3最後の資料から真相に進むクリック。
- `modificationPlayed.*`に保存、再生完了または状態回復可能なルールとする。再訪・リロード・Backによる重複や無限ループを防ぐ。
- 既存moduleの完了イベント／Promise仕様を確認してから呼び出し、画面遷移によるアニメ途中遮断を避ける。未確認の関数名を文書に新造しない。

## 11. デバッグ機能（通常公開では隠す）

- 既存のデバッグmodeへ作品stateをマッピングする。PHASE0/1/2/3/真相到達、訪問済み・絵馬発見・祭神発見・各帳面読了・登録番号・modificationPlayedを参照できること。
- デバッグショートカットやresetの詳細は`modules/`原本に従う。**既存のショートカットを上書き／新設しない**。
- 任意PHASEを選択した際はそれ以前の前提条件を整合させる（例：PHASE3なら参拝済＋絵馬発見＋祭神発見）。単純な数値変更だけで帳面hotspotが消えないようにする。
- デバッグUI・テスト番号・チート導線は本番の通常プレイに露出させない。

## 12. 探索リセット

1. Headerの「探索リセット」をクリック。PCはHeader、SPはハンバーガー**の横で常時表示**。
2. 確認メッセージ：**「探索の進行状況をリセットして、最初から始めますか？」**／「リセットする」「キャンセル」。
3. 承認した場合のみ作品stateと既存modulesの作品関連状態を初期化、参拝番号も削除。他作品・無関係のlocalStorageは消去しない。
4. TOP `index.html` に戻る。すべての異常は未発見、資料未解放、参拝未完へ戻る。
5. リセット後のBack/Forwardや別タブの旧状態再表示を防止。
